## Authentication Methods

Dayslla Lays Documentation supports multiple authentication methods to ensure secure access to your documentation spaces. Choose the method that best fits your use case, whether you're building integrations or accessing the API directly.

<Tabs>
  <Tab title="API Keys" icon="key">
    API keys provide a simple way to authenticate API requests. Generate keys in your dashboard and include them in your requests.

    <Steps>
      <Step title="Generate API Key" icon="plus">
        Navigate to your account settings and create a new API key.
      </Step>
      <Step title="Store Securely" icon="lock">
        Keep your API key secure and never expose it in client-side code.
      </Step>
      <Step title="Use in Requests" icon="send">
        Include the key in the Authorization header of your API calls.
      </Step>
    </Steps>

    <CodeGroup tabs="cURL,JavaScript,Python">
      ```bash
      curl -H "Authorization: Bearer YOUR_API_KEY" \
           https://api.dayslla-lays.com/v1/docs
      ```
      ```javascript
const response = await fetch('https://api.dayslla-lays.com/v1/docs', {
  headers: {
    'Authorization': `Bearer ${process.env.API_KEY}`
  }
});
      ```
      ```python
import requests

headers = {'Authorization': f'Bearer {api_key}'}
response = requests.get('https://api.dayslla-lays.com/v1/docs', headers=headers)
      ```
    </CodeGroup>
  </Tab>
  <Tab title="OAuth 2.0" icon="user">
    OAuth 2.0 provides more granular access control and is ideal for applications that need user-specific permissions.

    <Callout kind="info">OAuth 2.0 is recommended for web applications and user-facing integrations.</Callout>

    <Expandable title="OAuth Flow Details" default-open="false">
      The OAuth 2.0 flow involves redirecting users to our authorization endpoint, where they grant permissions, and receiving an access token in return.
    </Expandable>
  </Tab>
  <Tab title="JWT Tokens" icon="shield">
    JSON Web Tokens offer stateless authentication and can carry user information within the token itself.

    <Request tabs="cURL" show-lines="true">
      ```bash
      curl -X POST https://api.dayslla-lays.com/v1/auth/token \
           -H "Content-Type: application/json" \
           -d '{"username":"your_username","password":"your_password"}'
      ```
    </Request>

    <Response tabs="Success" show-lines="false">
      ```json
      {
        "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
        "token_type": "Bearer",
        "expires_in": 3600
      }
      ```
    </Response>
  </Tab>
</Tabs>

## Security Best Practices

When implementing authentication in your applications, follow these security guidelines to protect your documentation and user data.

<Columns cols={2}>
  <Card title="Key Rotation" icon="refresh-cw" href="#">
    Regularly rotate your API keys to minimize security risks.
  </Card>
  <Card title="Environment Variables" icon="settings" href="#">
    Store sensitive credentials in environment variables, not in code.
  </Card>
</Columns>

## Troubleshooting

If you're experiencing authentication issues, check these common problems and their solutions.

<ExpandableGroup>
  <Expandable title="Invalid API Key" default-open="false">
    Verify that your API key is correct and hasn't expired. Check the key format and ensure it's properly encoded.
  </Expandable>
  <Expandable title="Permission Denied" default-open="false">
    Ensure your authentication method has the required permissions for the requested operation.
  </Expandable>
  <Expandable title="Token Expired" default-open="false">
    Access tokens have a limited lifespan. Refresh them using the refresh token or re-authenticate.
  </Expandable>
</ExpandableGroup>

<Callout kind="danger">Never share your authentication credentials publicly or commit them to version control.</Callout>

By implementing proper authentication, you ensure that only authorized users can access and modify your documentation spaces, maintaining the integrity and security of your content.
